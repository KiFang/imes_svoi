# Свои в ИМЭС

Сайт групп по интересам для студентов, выпускников и абитуриентов ИМЭС: лента событий вуза и студентов, группы, граф интересов, регистрация с подтверждением почты и студенческого, профиль.

Сайт работает в двух режимах. Это одна и та же страница, режим выбирается настройками.

| Режим | Где хранятся данные | Когда нужен |
|---|---|---|
| Демо | В браузере (localStorage) | Показать идею и проверить интерфейс. Работает на любом бесплатном хостинге без настройки |
| Сервер | В базе Supabase (Postgres, вход по почте, закрытое хранилище файлов) | Настоящие пользователи, подтверждение почты, проверка студенческого |

## Структура

```
site/                       статический сайт (HTML, CSS, JavaScript без сборки)
  index.html                основное приложение
  admin.html                панель проверяющего (только режим «Сервер»)
  css/app.css               оформление, светлая и тёмная тема
  js/app.js                 интерфейс: лента, группы, граф, регистрация, профиль
  js/api.js                 выбор режима по настройкам
  js/api-mock.js            демо-режим
  js/api-supabase.js        режим «Сервер»
  js/rules.js               правила доступа (те же правила стоят в базе)
  js/config.js              настройки сервера (в демо-режиме пустые)
supabase/
  migrations/0001_init.sql  таблицы, права доступа, правила вступления, проверка студенческого
  seed.sql                  примеры тем, групп и событий
  functions/telegram-auth/  вход через Telegram с проверкой подписи
tests/                      автоматические проверки правил и демо-режима
.github/workflows/pages.yml публикация на GitHub Pages
docs/                       статья с обоснованием проекта
```

## Роли и ограничения

- **Студент** и **выпускник** получают полный доступ после того, как проверяющий подтвердил студенческий (или диплом).
- **Абитуриент** и любой пользователь до проверки: можно смотреть всё, отмечать «Пойду» и вступать в открытые группы, не больше трёх. Закрытые группы, предложение событий и создание групп недоступны.
- Роль выбирается при регистрации, но сама по себе ничего не открывает. Доступ меняет только статус проверки, который ставит проверяющий.
- Эти правила проверяет база данных (политики RLS и триггеры). Обойти их через консоль браузера нельзя.

## Запуск на своём компьютере

```bash
npx serve site        # откройте адрес из терминала
npm test              # проверки правил и демо-режима
```

## Публикация

### Вариант 1. GitHub Pages через Actions (бесплатно)

1. Settings → Pages → Source: **GitHub Actions**.
2. Любое изменение в ветке `main` запускает `.github/workflows/pages.yml`: тесты, затем публикация папки `site/`.
3. Адрес сайта появится в логе задачи `deploy` и в Settings → Pages.

Важно: на бесплатном тарифе GitHub Pages работает только для **публичных** репозиториев. В этом репозитории нет секретов (ключ `anon` публичный по замыслу Supabase), поэтому его можно открыть. Если репозиторий должен остаться закрытым, папку `site/` можно так же бесплатно разместить на Netlify, Cloudflare Pages или Vercel: сборка не нужна, достаточно указать папку `site`.

### Вариант 2. Подключить сервер (Supabase)

1. Создайте проект на supabase.com (бесплатного тарифа хватает для теста).
2. SQL Editor: выполните `supabase/migrations/0001_init.sql`, затем `supabase/seed.sql`.
3. Authentication → Email Templates → Magic Link: добавьте в письмо код `{{ .Token }}` (сайт просит 6-значный код). Встроенная почта Supabase ограничена по числу писем в час, для реальных пользователей подключите свой SMTP (Authentication → SMTP).
4. Settings → API: скопируйте Project URL и ключ `anon`.
5. В репозитории: Settings → Secrets and variables → Actions → вкладка **Variables** → создайте `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Запустите workflow заново: он запишет их в `site/js/config.js`.
6. Первый проверяющий. Зарегистрируйтесь на сайте, затем в SQL Editor:
   ```sql
   insert into public.admins (user_id) select id from auth.users where email = 'ваша@почта';
   ```
   Панель проверки находится по адресу `/admin.html`.

### Вход через Telegram (по желанию)

1. Создайте бота у @BotFather, командой `/setdomain` укажите адрес сайта.
2. `supabase functions deploy telegram-auth` и `supabase secrets set TELEGRAM_BOT_TOKEN=...`.
3. Добавьте переменную репозитория `TELEGRAM_BOT` с именем бота без `@` и перезапустите workflow.

Функция проверена только по документации Telegram, на реальном боте ещё не запускалась. MAX добавляется так же: отдельная функция проверки подписи и кнопка рядом с Telegram.

## Перенос на российские серверы

Для тестов данные могут жить в Supabase. Для рабочей версии данные граждан РФ нужно хранить на серверах в России. Схема `0001_init.sql` обычная Postgres, её можно развернуть на VPS в России вместе с self-hosted Supabase (официальная сборка на Docker). Сайт при этом не меняется: достаточно подставить другие `SUPABASE_URL` и ключ.
